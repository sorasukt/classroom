# Classroom by /sorasukt

ระบบเช็คชื่อนักเรียนสำหรับครู โดย Host หน้าเว็บ `index.html` ผ่าน GitHub Pages และใช้ Cloudflare Worker สำหรับ API, Auth0 callback, D1 และ R2 เท่านั้น

## ความสามารถ

- Dashboard สรุปห้องเรียน นักเรียน อัตราเข้าเรียน 14 วัน และคาบวันนี้
- จัดการห้องเรียนและรายชื่อนักเรียน
- เช็คชื่อสถานะ มา / สาย / ขาด / ลา
- สถิติและประวัติย้อนหลังรายบุคคล
- บันทึกและแก้ไขแผนการสอนรายห้องเรียน
- ส่งออก CSV แบบ UTF-8 BOM รองรับภาษาไทยใน Excel
- สร้างลิงก์สรุปรายวันและแชร์ผ่าน LINE
- Responsive พร้อม bottom navigation บนมือถือ
- D1 เป็นฐานข้อมูลหลัก และ R2 เก็บ audit, snapshot การเช็คชื่อ และสำเนา CSV
- Auth0 Universal Login พร้อม signed session สำหรับเว็บ GitHub Pages
- แยกข้อมูลตามบัญชี: อีเมลทั่วไปใช้พื้นที่ส่วนตัว และโดเมนโรงเรียนไทย `*.ac.th` ใช้พื้นที่ร่วมของโรงเรียน
- Role-based access: บัญชีโรงเรียนต้องมี Auth0 role `Admin` จึงจะเพิ่ม/ลบห้องเรียนและนักเรียนได้
- หน้า Admin สำหรับข้อมูลสถานศึกษา ปีการศึกษา ภาคเรียน และ Import CSV พร้อม Template
- ตารางบัญชีโรงเรียนสำหรับกำหนดอีเมล สิทธิ์ Admin/ผู้ใช้งาน และสถานะเป็นรายคน
- School Branding: แสดงข้อมูลสถานศึกษาบน Dashboard และอัปโหลดโลโก้แนวนอน/1:1 ไปยัง R2
- ทะเบียนนักเรียนกลาง: เก็บนักเรียนหนึ่งครั้งและลงทะเบียนคนเดียวกันได้หลายห้องเรียน
- ตารางเรียนกลาง: กำหนดคาบประจำสัปดาห์และสร้างรอบเช็คชื่อของวันนั้นให้อัตโนมัติ

## Product Roadmap

รายการนี้เก็บขอบเขตที่วางแผนไว้สำหรับพัฒนาต่อ เพื่อใช้เป็นหลักอ้างอิงร่วมกันใน Pull Request ถัดไป ระบบต้องรองรับผู้ใช้สองรูปแบบโดยไม่บังคับให้ครูรายบุคคลตั้งค่าระบบโรงเรียน

### รูปแบบการใช้งาน

| รูปแบบ | เหมาะสำหรับ | พื้นที่ข้อมูลและสิทธิ์ |
| --- | --- | --- |
| **พื้นที่สอนส่วนตัว** | ครู ติวเตอร์ อาจารย์พิเศษ หรือผู้สอนที่ดูแลชั้นเรียนของตนเอง | สมัครด้วยอีเมลทั่วไป ระบบสร้างพื้นที่ส่วนตัวให้อัตโนมัติ ผู้ใช้เป็นเจ้าของและจัดการห้อง นักเรียน ตารางเรียน แผนการสอน และรายงานของตนเองได้ทันที ไม่ต้องมี role Admin หรือข้อมูลสถานศึกษา |
| **พื้นที่สถานศึกษา** | โรงเรียนหรือหน่วยงานที่มีครูหลายคนและใช้ข้อมูลร่วมกัน | ใช้อีเมล `*.ac.th` และตารางสมาชิกของโรงเรียน ข้อมูลอยู่ในพื้นที่ร่วมตามโดเมน โดย Admin โรงเรียนควบคุมสมาชิก ห้องเรียน ทะเบียน และการตั้งค่าสถานศึกษา |

ข้อมูลของพื้นที่สอนส่วนตัวต้องไม่ถูกรวมกับพื้นที่สถานศึกษาอัตโนมัติ แม้ผู้ใช้คนเดียวกันจะมีหลายบัญชี การย้ายหรือคัดลอกข้อมูลระหว่างพื้นที่ต้องเป็นคำสั่งที่ผู้ใช้ยืนยันในอนาคต

### Phase 1 — พื้นฐานร่วมสำหรับครูและสถานศึกษา (ดำเนินการแล้ว)

#### ความสามารถร่วม

- [x] ทะเบียนนักเรียนกลาง แยกข้อมูลประจำตัว รหัสนักเรียน ห้องประจำ และผู้ปกครองออกจากรายชื่อรายห้อง
- [x] นักเรียนหนึ่งคนลงทะเบียนได้หลายห้องเรียน โดยประวัติการเช็คชื่อยังผูกกับบุคคลเดิม
- [x] เพิ่ม/พักใช้งานข้อมูลนักเรียน และเพิ่ม/นำรายชื่อออกจากห้องโดยไม่ลบประวัติเดิม
- [x] ตารางเรียนรายสัปดาห์ ระบุวัน เวลา ห้อง และครูผู้สอน
- [x] Worker Cron เตรียม attendance session ตามตารางเรียนทุกวัน และ Dashboard เตรียมซ้ำแบบ idempotent เมื่อเปิดใช้งาน
- [x] Import CSV เข้าทะเบียนกลางพร้อมลงทะเบียนเข้าห้อง รองรับข้อมูลผู้ปกครองและห้องประจำ
- [x] เช็คชื่อด้วยตนเอง สแกนบัตร และ QR สำหรับนักเรียน พร้อมรายงานและการแชร์ผ่าน LINE
- [x] อัปเดตรายชื่อบนหน้าครูทุก 5 วินาทีระหว่างเปิดรอบ QR โดยไม่ทับสถานะที่ครูกำลังแก้ไข
- [x] เปิดรอบเดิมซ้ำได้จนหมดเวลา พร้อม QR แบบขยายและรหัสเข้ารอบ 5 หลักที่ใช้ผ่าน `/checkin`
- [x] นักเรียนยืนยันด้วยรหัสนักเรียนแทนการเลือกรายชื่อ และอุปกรณ์ที่ผูกแล้วไม่ต้องกรอกรหัสซ้ำ

#### สำหรับครูผู้สอนรายบุคคล

- [x] สร้างพื้นที่สอนส่วนตัวจากบัญชีอีเมลทั่วไปโดยอัตโนมัติ และแยกข้อมูลด้วย Auth0 user ID
- [x] เจ้าของพื้นที่เพิ่ม แก้ไข และลบห้องเรียนหรือรายชื่อของตนเองได้ โดยไม่ต้องขอสิทธิ์ Admin
- [x] เปลี่ยนเมนู Admin เป็น “ตั้งค่าพื้นที่” และใช้คำว่า “ตารางสอนของฉัน”, “รายชื่อนักเรียนของฉัน” และ “กลุ่ม/ระดับ” ให้เหมาะกับครูรายบุคคล
- [x] ตั้งชื่อพื้นที่สอนหรือชื่อผู้สอน พร้อมปีการศึกษาและภาคเรียนได้ โดยข้อมูลที่ตั้งจะแสดงบน Dashboard
- [x] เติมชื่อเจ้าของบัญชีเป็นชื่อผู้สอนเริ่มต้นเมื่อสร้างคาบ และยังแก้ไขหรือลบได้
- [x] ใช้ทะเบียน ตารางสอน Import CSV เช็คชื่อ แผนการสอน และรายงานได้โดยไม่ต้องตั้งชื่อโรงเรียนหรืออัปโหลดโลโก้
- [x] เก็บช่องข้อมูลผู้ปกครองไว้เป็น “ผู้ติดต่อ” และห้องประจำเป็น “กลุ่ม/ระดับ” เพื่อรองรับติวเตอร์และอาจารย์พิเศษ

#### สำหรับสถานศึกษา

- [x] แยกพื้นที่ร่วมตามโดเมนโรงเรียนและตรวจสมาชิกก่อนอนุญาตให้เข้าใช้
- [x] Admin จัดการบัญชี ห้องเรียน ทะเบียนนักเรียน ข้อมูลสถานศึกษา และ School Branding
- [x] ครูทั่วไปดูข้อมูล เช็คชื่อ ทำแผนการสอน รายงาน และแชร์ได้ โดยไม่แก้โครงสร้างหลักของโรงเรียน

หมายเหตุ: attendance session ปัจจุบันมีหนึ่งรายการต่อห้องเรียนต่อวัน หากต้องเช็คชื่อห้องเดียวกันหลายคาบในวันเดียว จะขยายเป็น period-level session ใน Phase ต่อไป

### Phase 2 — งานประจำวันของครูและการติดตามนักเรียน (วางแผน)

Phase 2 ขยายจากระบบเช็คชื่อเป็นพื้นที่เรียนของครูและนักเรียน โดยแบ่งการพัฒนาเป็น 2A–2D ตามลำดับ รายการทั้งหมดด้านล่างยังไม่ใช่ความสามารถที่เปิดใช้งานแล้ว การแยกพื้นที่ตามอีเมลในหัวข้อความสามารถและการติดตั้งเป็นพฤติกรรมปัจจุบัน ส่วน 2A จะเพิ่มสมาชิกและบทบาทรายพื้นที่โดยรักษาข้อมูลและสิทธิ์ผู้ใช้เดิม

| ระยะ | ขอบเขต |
| --- | --- |
| **2A** | วิธีเข้าพื้นที่นักเรียน ลิงก์ลงทะเบียน สมาชิก บทบาท และการตรวจหลักฐาน |
| **2B** | สั่งงาน ส่งงาน ตรวจงาน สมุดคะแนน และข้อเสนอแนะ |
| **2C** | กิจกรรมในคาบเรียน คะแนนด่วน สุ่มชื่อ แบ่งกลุ่ม และแบบประเมิน |
| **2D** | Dashboard ประจำวัน ศูนย์ติดตามนักเรียน และงานบริหารการสอน |

#### Phase 2A — การเข้าพื้นที่นักเรียนและการยืนยันตัวตน

##### วิธีเข้าใช้งานที่ครูหรือโรงเรียนเลือกได้

- [ ] ตั้งค่าวิธีเข้าพื้นที่นักเรียนระดับพื้นที่ โดยเจ้าของพื้นที่หรือ Admin เลือกได้ว่าจะอนุญาตให้ครูปรับรายห้องหรือไม่

| รูปแบบ | ขั้นตอน | เงื่อนไข |
| --- | --- | --- |
| **รหัสนักเรียนเข้าได้ทันที** | เปิดลิงก์หรือกรอกรหัสห้อง แล้วกรอกรหัสนักเรียน | ตรวจว่ามีชื่อในทะเบียนห้อง ไม่ต้องมีอีเมล สมัครบัญชี หรือรออนุมัติ |
| **Auth0 พร้อมขั้นตอนอนุมัติ** | เปิดลิงก์ลงทะเบียน สมัครหรือเข้าสู่ระบบ ยืนยันอีเมล และกรอกรหัสนักเรียน | ใช้อีเมลโดเมนใดก็ได้ ครูตรวจทะเบียน และขอหลักฐานเฉพาะเมื่อจำเป็น |

- [ ] แจ้งข้อจำกัดของโหมดรหัสนักเรียนตอนตั้งค่า: ผู้ที่รู้รหัสห้องและรหัสนักเรียนอาจสวมรอยได้ การจำกัดการลองไม่ใช่การยืนยันตัวบุคคล การเปิดดูคะแนนและข้อเสนอแนะส่วนตัวในโหมดนี้ต้องเป็นตัวเลือกที่ครูเปิดเพิ่ม
- [ ] สร้างลิงก์ลงทะเบียนที่ผูกกับพื้นที่/ห้อง กำหนดวันหมดอายุ ปิดรับสมัคร และเพิกถอนลิงก์ได้
- [ ] ตรวจสอบสถานะลิงก์และสมาชิกก่อนเปิดข้อมูลห้อง การมีลิงก์เพียงอย่างเดียวไม่ให้สิทธิ์อ่านทะเบียนหรือคะแนน
- [ ] ผูกบัญชี Auth0 กับทะเบียนนักเรียนภายในพื้นที่ รองรับนักเรียนหนึ่งคนหลายห้อง และรหัสนักเรียนซ้ำกันข้ามพื้นที่
- [ ] หากทะเบียนถูกผูกกับบัญชีอื่นแล้ว ให้ตรวจสอบหรือกู้บัญชีโดยครู ไม่ย้ายเจ้าของบัญชีอัตโนมัติ
- [ ] รองรับคำเชิญเฉพาะบุคคลที่ผูกทะเบียนไว้แล้ว การออกจากระบบบนเครื่องส่วนกลาง และการเพิกถอน session

##### สมาชิก บทบาท และอีเมลโรงเรียน

- [ ] แยกบทบาทเจ้าของพื้นที่, Admin, ครู และนักเรียนตามสมาชิกของแต่ละพื้นที่ แทนการตัดสินบทบาทจากโดเมนอีเมลอย่างเดียว
- [ ] กำหนดครูผู้ดูแลแต่ละห้องก่อนเปิดการสั่งงาน ให้ครูจัดการเฉพาะห้องที่ได้รับมอบหมาย
- [ ] เพิ่มตัวเลือกเสริม “ให้บัญชีใหม่ที่ใช้อีเมลโรงเรียนเข้าสู่พื้นที่นักเรียนโดยอัตโนมัติ” โดยใช้โดเมนที่สถานศึกษายืนยันและตั้งค่าไว้ พร้อมตรวจอีเมลที่ยืนยันแล้ว ไม่ใช้โดเมนอีเมลทั่วไปของ Admin เช่น Gmail เป็นโดเมนโรงเรียน
- [ ] การเข้าสู่หน้านักเรียนอัตโนมัติยังต้องผ่านเงื่อนไขสมาชิก/การอนุมัติก่อนดูงานหรือคะแนน และไม่ลดสิทธิ์ Admin หรือครูเดิม
- [ ] Admin กำหนดหรือเปลี่ยนสถานะเป็นครูภายหลังได้ พร้อมกำหนดห้องที่รับผิดชอบ และรองรับการสลับพื้นที่/บทบาท
- [ ] ตรวจสิทธิ์ฝั่ง API ทุกครั้งที่อ่านงาน ส่งงาน ดูคะแนน และเข้าถึงไฟล์ ป้องกันการเปลี่ยน ID เพื่ออ่านข้อมูลคนอื่นหรือข้ามพื้นที่

##### รหัสห้องและการป้องกันการเดา

- [ ] สร้างรหัสห้องฝั่งเซิร์ฟเวอร์ด้วยแหล่งสุ่มที่แข็งแรงทางการเข้ารหัส เช่น `crypto.getRandomValues()` ไม่ใช้ `Math.random()` หรือเลขเรียง และไม่อ้างว่า API รับประกัน Hardware True Random
- [ ] ใช้รหัสตัวเลข 16 หลักแบ่งกลุ่มเพื่ออ่านง่าย พร้อม QR/ลิงก์ สุ่มอย่างเท่าเทียม ตรวจรหัสซ้ำและสร้างใหม่เมื่อชนกัน
- [ ] แยกรหัสเข้าห้องออกจากรหัสเช็คชื่อ 5 หลักเดิม กำหนดวันหมดอายุและหมุนรหัสได้โดยไม่ลบสมาชิกเดิม
- [ ] จำกัดและหน่วงการลองหลายระดับ ทั้งบัญชี อุปกรณ์ เครือข่าย และภาพรวม โดยคำนึงถึง Wi-Fi โรงเรียนร่วมกันและไม่เปิดช่องให้ผู้โจมตีล็อกทั้งห้อง
- [ ] ไม่เปิดเผยว่ารหัสห้องหรือรหัสนักเรียนส่วนใดถูกต้อง ไม่แสดงรายชื่อก่อนมีสิทธิ์ และบันทึกเหตุการณ์ผิดปกติโดยไม่เก็บรหัสลับ
- [ ] ตรวจความเสี่ยงจากการเดารหัส การรั่วของลิงก์ การลองพร้อมกัน และการสวมรอยจากเพื่อนร่วมชั้นก่อนเปิดใช้

##### ตรวจทะเบียนและหลักฐานภายในระบบ

- [ ] ใช้ทะเบียนของครูหรือโรงเรียนเป็นฐานตรวจสอบ ไม่พึ่งบริการตรวจนักเรียนภายนอกที่คิดค่าบริการต่อคน
- [ ] ให้ครูตรวจรายชื่อหรือคำเชิญเฉพาะบุคคลก่อน และขอบัตรนักเรียน/หลักฐานอื่นตามนโยบายห้องเฉพาะกรณีจำเป็น
- [ ] นักเรียนปิดข้อมูลที่ไม่จำเป็นบนหลักฐานได้ เช่น เลขประจำตัวประชาชนและที่อยู่ การอัปโหลดภาพสำเร็จไม่เท่ากับผ่านการตรวจ
- [ ] รองรับสถานะรอตรวจ ขอข้อมูลเพิ่ม อนุมัติ ปฏิเสธ ยกเลิก และหลักฐานหมดอายุ
- [ ] เก็บไฟล์ส่วนตัว ให้เฉพาะผู้ตรวจที่ได้รับสิทธิ์เข้าถึง ตรวจชนิด/เนื้อหาและขนาดไฟล์ และป้องกันการเปิดไฟล์ข้ามพื้นที่

##### ข้อบังคับการลบหลักฐานและข้อมูลอ่อนไหว

เพดานนี้ต้องทำพร้อม Phase 2A และครูหรือโรงเรียนขยายเวลาเกิน 7 วันไม่ได้ ไม่รอระบบ retention ทั่วไปใน Phase 4

| เหตุการณ์ที่เกิดก่อน | การดำเนินการ |
| --- | --- |
| อนุมัติคำขอ | ลบหลักฐานทันที |
| ปฏิเสธคำขอ | ลบหลักฐานทันที การสมัครใหม่ต้องแนบใหม่ |
| ครบ 7 วันนับจากอัปโหลดแต่ละไฟล์ | ลบอัตโนมัติแม้ยังไม่ตรวจ และให้ส่งใหม่หากยังต้องใช้หลักฐาน |
| นักเรียนยกเลิกคำขอ | ลบหลักฐานทันที |

- [ ] ใช้กฎเดียวกันกับข้อมูลอ่อนไหวที่กรอกเพื่อยืนยันตัวตน โดยนับอายุจากเวลารับข้อมูล
- [ ] เมื่อหลักฐานหมดอายุให้คำขอเป็น “หลักฐานหมดอายุ” การอัปโหลดเพิ่มไม่ต่ออายุไฟล์เก่า
- [ ] ลบต้นฉบับ ภาพย่อ ข้อความที่อ่านจากภาพ และข้อมูลอ่อนไหวประกอบคำขอ รวมถึงสำเนาชั่วคราวที่ระบบสร้าง
- [ ] ไม่คัดลอกหลักฐานหรือเนื้อหาอ่อนไหวลง audit log, snapshot หรือ backup ที่เก็บเกินกำหนด
- [ ] บังคับหมดสิทธิ์อ่านเมื่อครบกำหนดหรือมีคำตัดสิน มีงานลบอัตโนมัติ หากลบไม่สำเร็จให้ปิดการเข้าถึงทันที ลองลบซ้ำ และแจ้งผู้ดูแลจนลบสำเร็จ
- [ ] เก็บต่อเฉพาะประวัติที่จำเป็น เช่น สถานะคำขอ ผู้ตรวจ และเวลาตรวจ โดยไม่คัดลอกเนื้อหาหลักฐานลงหมายเหตุ
- [ ] แยกนโยบายเก็บชื่อ รหัสนักเรียน งาน และคะแนนที่ใช้ในการเรียนออกจากหลักฐานยืนยันตัวตน และแยกจากอายุ device binding ของระบบเช็คชื่อเดิม

#### Phase 2B — สั่งงาน ส่งงาน และสมุดคะแนน

- [ ] ครูสร้างฉบับร่าง ตั้งเวลาเผยแพร่ ระบุคำสั่ง แนบไฟล์/ลิงก์ คะแนนเต็ม กำหนดส่ง และวันปิดรับงาน
- [ ] มอบหมายทั้งห้องหรือเฉพาะบุคคล นักเรียนเห็นเฉพาะงานที่ตนได้รับและเผยแพร่แล้ว
- [ ] นักเรียนส่งข้อความ ลิงก์ หรือไฟล์ พร้อมหลักฐานเวลาส่งสำเร็จจากเซิร์ฟเวอร์
- [ ] กำหนดส่งช้า ส่งแก้ไข และงานแก้ตัวได้ เก็บประวัติการส่งแต่ละรอบ ไม่เขียนทับไฟล์เดิมทั้งหมด
- [ ] แยกสถานะยังไม่ส่ง ส่งแล้ว ตรวจแล้ว ส่งช้า ให้แก้ไข และยกเว้นงาน
- [ ] ครูตรวจงาน ให้คะแนนและข้อเสนอแนะส่วนตัว พร้อมเลือกวันเผยแพร่ผล
- [ ] สมุดคะแนนกำหนดหมวด คะแนนเต็ม น้ำหนัก และเกณฑ์ตัดเกรดรายวิชา เช่น งาน กิจกรรม สอบย่อย กลางภาค และปลายภาค
- [ ] แยกยังไม่ตรวจ ไม่ส่ง ยกเว้น และได้ศูนย์ เพื่อคำนวณคะแนนอย่างถูกต้อง พร้อมประวัติการแก้ไขและส่งออก Excel/CSV
- [ ] เก็บงาน คะแนน และประวัติใน D1; เก็บไฟล์ใน R2 แบบ private พร้อมตรวจสิทธิ์ทุกครั้งที่ดาวน์โหลด
- [ ] เพิ่มพื้นที่นักเรียน `/student` ที่มีวันนี้ งานของฉัน ห้องเรียน และผลการเรียน โดยรักษา `/checkin` สำหรับเช็คชื่อรวดเร็ว

#### Phase 2C — กิจกรรมและเครื่องมือในคาบเรียน

- [ ] หน้า “เริ่มคาบเรียน” รวมเช็คชื่อ งาน และกิจกรรม โดยเลือกให้คะแนนหรือฝึกอย่างเดียวได้
- [ ] ให้คะแนนด่วนรายบุคคล/กลุ่ม สำหรับตอบคำถาม การนำเสนอ และการมีส่วนร่วม พร้อมหมายเหตุและประวัติแก้ไข/ยกเลิก
- [ ] สุ่มนักเรียนจากผู้ที่มาเรียน เลือกไม่ซ้ำจนกว่าจะครบ และข้ามคนที่ไม่พร้อมได้
- [ ] แบ่งกลุ่มแบบสุ่มหรือจัดเอง บันทึกกลุ่มประจำ และกำหนดบทบาทสมาชิก
- [ ] จับเวลาทำงาน อภิปราย หรือสอบย่อย พร้อมโหมดแสดงเต็มจอ
- [ ] คำถามระหว่างเรียนแบบปรนัย ถูก–ผิด คำตอบสั้น และโหวต พร้อมแสดงผลรวม
- [ ] แบบประเมินก่อนจบคาบสำหรับความเข้าใจ สิ่งที่ยังสงสัย หรือคำตอบสั้น
- [ ] เกณฑ์ประเมินแบบ rubric สำหรับพูด อ่าน เขียน ชิ้นงาน และการทำงานกลุ่ม
- [ ] ประเมินตนเองและเพื่อน โดยครูตรวจทานก่อนเลือกนำไปรวมคะแนน
- [ ] หน้าฉายจอซ่อนคะแนนส่วนตัวเป็นค่าเริ่มต้น
- [ ] โมดูลเลือกใช้สำหรับการอ่าน–คิดวิเคราะห์–เขียน คุณลักษณะ และกิจกรรมพัฒนาผู้เรียน โดยสถานศึกษากำหนดแบบประเมิน/เกณฑ์เอง

#### Phase 2D — Dashboard และศูนย์ติดตามนักเรียน

- [ ] หน้าแรกครูแสดงคาบวันนี้ คาบถัดไป งานใกล้กำหนด งานรอตรวจ และนักเรียนที่ควรติดตามพร้อมเหตุผล
- [ ] หน้าแรกนักเรียนแยกงานใกล้ส่ง งานค้าง และงานที่ต้องแก้ไข
- [ ] รวมข้อมูลขาดเรียน มาสาย งานค้าง และผลการเรียน พร้อมเกณฑ์แจ้งเตือนที่ครูปรับได้
- [ ] คำนวณติดตามจากคาบที่บันทึกแล้วและงานที่ถึงกำหนดจริง ไม่นับงานยกเว้น

- [ ] ทำงานแบบกลุ่ม เช่น เลือกนักเรียนหลายคน เปลี่ยนสถานะ ย้ายห้อง พักใช้ หรือส่งออกข้อมูลพร้อมกัน

- [ ] แม่แบบแผนการสอนและการคัดลอกแผนไปยังห้องหรือวันที่อื่น

### Phase 4 — ความพร้อมใช้งาน ความปลอดภัย และข้อมูลส่วนบุคคล

- [ ] สร้างบัตรนักเรียนพร้อม Barcode/QR จากทะเบียนกลาง
- [ ] PWA ใช้งานออฟไลน์ เก็บคิวเช็คชื่อในเครื่อง และ sync เมื่อกลับมาออนไลน์
- [ ] Audit log สำหรับการแก้ไขข้อมูลสำคัญ พร้อมเปรียบเทียบก่อน/หลังและกู้คืนรายการที่ลบโดยไม่ตั้งใจ
- [ ] นโยบาย retention, consent, export/delete ข้อมูลส่วนบุคคล และเครื่องมือรองรับ PDPA
- [ ] สำรองข้อมูล ตรวจสอบความสมบูรณ์ และขั้นตอนกู้คืน D1/R2 แยกตามพื้นที่ส่วนตัวและพื้นที่สถานศึกษา
- [ ] ขั้นตอนย้ายหรือคัดลอกข้อมูลระหว่างพื้นที่ โดยต้องแสดงขอบเขตข้อมูลและขอการยืนยันก่อนดำเนินการ

## การจัดเก็บข้อมูล

- **D1 (ข้อมูลหลัก):** ห้องเรียน ทะเบียนนักเรียน การลงทะเบียนหลายห้อง ตารางเรียน การเช็คชื่อ แผนการสอน และลิงก์แชร์ ระบบอ่านข้อมูลสำหรับหน้าเว็บและรายงานจาก D1
- **R2 (สำเนาและไฟล์):** เป็น bucket แบบ private ที่เข้าถึงผ่าน Worker binding เท่านั้น
  - `audit/YYYY-MM-DD/*.json` เก็บเหตุการณ์สร้าง แก้ไข ลบ และแชร์ เพื่อใช้ตรวจสอบย้อนหลัง
  - `snapshots/attendance/{classroom_id}/{date}.json` เก็บภาพล่าสุดของการเช็คชื่อแต่ละวัน
  - `exports/*.csv` เก็บสำเนา CSV ที่ผู้ใช้ส่งออก

Worker จะบันทึก D1 ให้สำเร็จก่อน แล้วจึงส่งงานสำเนาไป R2 แบบ background ดังนั้น R2 ขัดข้องชั่วคราวจะไม่ทำให้การเช็คชื่อใน D1 สูญหาย ข้อมูลนักเรียนใน R2 ไม่ได้เปิดเป็น public URL

## ติดตั้ง

1. สร้าง D1 และ R2

   ```bash
   npx wrangler d1 create classroom-db
   npx wrangler r2 bucket create classroom-exports
   ```

2. นำ `database_id` ที่ได้รับมาแทนค่า `REPLACE_WITH_D1_DATABASE_ID` ใน `wrangler.toml`

3. สร้าง Auth0 Application ประเภท **Regular Web Application** แล้วตั้งค่า:

   - Allowed Callback URLs: `https://classroom.sorasukt.com/api/auth/callback`
   - Allowed Logout URLs: `https://sorasukt.com/classroom/`, `https://sorasukt.github.io/classroom/`
   - Allowed Web Origins: `https://sorasukt.com`, `https://www.sorasukt.com`, `https://sorasukt.github.io`

   จากนั้นแก้ `AUTH0_DOMAIN` และ `AUTH0_CLIENT_ID` ใน `wrangler.toml`

   สำหรับสิทธิ์โรงเรียน ให้สร้าง Auth0 role ชื่อ **Admin**, มอบ role นี้แก่ผู้ดูแลโรงเรียน แล้วสร้าง Action ประเภท **Login / Post Login** จากไฟล์ [`auth0/post-login.js`](auth0/post-login.js) จากนั้น Deploy และลาก Action เข้า Login Flow ระบบจะอ่าน claim `https://classroom.sorasukt.com/roles` จาก Auth0 ทุกครั้งที่เข้าสู่ระบบ ผู้ใช้ต้องออกและเข้าสู่ระบบใหม่หลังเปลี่ยน role

4. ตั้ง Auth0 Client Secret เป็น Worker secret

   ```bash
   npx wrangler secret put AUTH0_CLIENT_SECRET
   ```

5. Deploy

   ```bash
   npx wrangler deploy
   ```

ตาราง D1 ถูกจัดการด้วยไฟล์ใน `migrations/` และต้อง apply ก่อน Deploy Worker ระบบไม่สร้างหรือแก้ schema ระหว่างคำขอของผู้ใช้ Migration `0002_tenant_admin_import.sql` เพิ่มการแยก tenant และการตั้งค่าหน้า Admin โดยข้อมูลห้องเรียนเดิมจะถูกผูกกับผู้ใช้คนแรกที่เรียก `/api/bootstrap` หลัง migration

## สิทธิ์และการ Import CSV

- **อีเมลทั่วไป:** เป็นเจ้าของพื้นที่ส่วนตัว สามารถเพิ่มและลบห้องเรียน/นักเรียน รวมถึงใช้หน้า Admin และ Import CSV ได้
- **Admin คนแรกของโรงเรียน:** ต้องยืนยันอีเมลและมี Auth0 role `Admin` เมื่อเข้าสู่ระบบ Worker จะเพิ่มอีเมลนี้ลงตารางบัญชีโรงเรียนเป็น Admin อัตโนมัติ
- **อีเมลโรงเรียนที่ถูกเพิ่มเป็น Admin:** จัดการข้อมูลร่วม เพิ่ม/ลบห้องเรียนและนักเรียน ตั้งค่า Import CSV และเพิ่ม/ลบบัญชีอื่นได้
- **อีเมลโรงเรียนที่ถูกเพิ่มเป็นผู้ใช้งาน:** ดูข้อมูล เช็คชื่อ จัดการแผนการสอน รายงาน และแชร์ได้ แต่เพิ่ม/ลบห้องเรียนและนักเรียนไม่ได้
- **อีเมล `*.ac.th` ที่ยังไม่อยู่ในตาราง:** จะไม่สามารถเข้าถึงพื้นที่ร่วมของโรงเรียน แม้ใช้อีเมลโดเมนเดียวกัน
- **อีเมลโรงเรียนที่ยังไม่ยืนยัน:** จะไม่เข้าถึงพื้นที่ร่วมของโรงเรียนจนกว่าจะยืนยันอีเมลสำเร็จ

หน้า Admin จะแสดงตารางบัญชีโรงเรียน โดยรับเฉพาะอีเมลที่ลงท้ายด้วยโดเมนเดียวกับ Admin เช่น `teacher@school.ac.th` และ `staff@school.ac.th` Admin สามารถกำหนดสิทธิ์ `Admin` หรือ `ผู้ใช้งาน` และเปิด/ระงับบัญชีได้ ระบบป้องกันไม่ให้ Admin ลบ ลดสิทธิ์ หรือระงับบัญชีที่กำลังใช้งานอยู่เพื่อป้องกันการล็อกตัวเองออก

## QR และ Barcode Attendance

- ครูสแกน Barcode หรือ QR บนบัตรนักเรียนจากกล้อง หรือกรอกรหัสด้วยตนเอง ระบบจับคู่กับ `student_code` และบันทึกสถานะมาเรียน
- ครูสร้าง QR รับเช็คชื่อประจำห้องและวันที่ กำหนดอายุได้ 10–60 นาที และปิดรับก่อนหมดเวลาได้
- นักเรียนเปิดหน้ารับเช็คชื่อบน Worker โดยไม่ต้องเข้าสู่ระบบ กรอกรหัสนักเรียนครั้งแรกแล้วบันทึกสถานะมาเรียน
- นักเรียนที่สแกน QR ไม่สะดวกสามารถเข้า `https://classroom.sorasukt.com/checkin` และกรอกรหัสเข้ารอบ 5 หลัก
- ระหว่างรอบยังไม่หมดเวลา ครูเปิดหน้าต่าง QR กลับมาได้โดยใช้ QR และรหัสเดิม และแตะ QR เพื่อแสดงแบบเต็มจอ
- หน้าครูดึงสถานะล่าสุดทุก 5 วินาทีขณะรอบ QR ทำงาน โดยรักษาการแก้ไขที่ครูยังไม่ได้กดบันทึก
- Worker สร้าง device cookie แบบ `HttpOnly`, `Secure`, `SameSite=Lax` และเก็บเฉพาะค่าแฮชใน D1
- อุปกรณ์หนึ่งเครื่องผูกกับนักเรียนหนึ่งคนต่อห้องเป็นเวลาอย่างน้อย 7 วัน ต้องกดรีเซ็ตหลังครบกำหนดก่อนเลือกชื่อใหม่
- Token ใน QR ถูกเก็บใน D1 แบบ SHA-256 และหน้ารับเช็คชื่อไม่อนุญาตให้ search engine ทำดัชนี

Migration `0005_qr_checkin.sql` เพิ่ม `student_code`, ตารางรอบรับเช็คชื่อ และตารางผูกอุปกรณ์

Migration `0006_phase1_school_operations.sql` ย้ายรายชื่อเดิมไปยัง `student_profiles`, สร้าง `classroom_enrollments` และ `timetable_entries` โดยรักษา ID นักเรียนเดิมไว้เพื่อคงประวัติ attendance และ device binding ทั้งหมด

Migration `0007_realtime_checkin_codes.sql` เพิ่มรหัสเข้ารอบ 5 หลัก ดัชนีค้นหารอบ และตารางจำกัดการลองรหัสผิด โดย route สาธารณะรองรับเฉพาะ `/checkin`, `/checkin/{token}` และ `/share/{token}` ส่วน route อื่นตอบหน้า 404

## GitHub Actions

Workflow `.github/workflows/deploy.yml` จะตรวจ syntax, migration และ Worker bundle ในทุก Pull Request เมื่อ merge เข้า `main` ระบบจะใส่ค่าจริงลงใน Wrangler config ชั่วคราวบน GitHub runner, ตรวจ D1, สร้าง R2 bucket หากยังไม่มี, apply D1 migrations, dry-run และ Deploy Worker ตามลำดับ รวมถึงรองรับการกด Run workflow เอง

เพิ่มค่าที่ `Settings → Secrets and variables → Actions` ดังนี้

### Secrets

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`
- `AUTH0_CLIENT_SECRET`

### Variables

- `D1_DATABASE_ID`
- `AUTH0_CLIENT_ID`

Workflow จะเรียก Wrangler โดยตรงเพื่อส่ง `AUTH0_CLIENT_SECRET` ไปเก็บเป็น Cloudflare Worker Secret ก่อน Deploy โดยอัตโนมัติ ส่วนกุญแจลงนาม session จะถูกสร้างแบบแยกบริบทจาก Client Secret ภายใน Worker และไม่ต้องตั้งค่าเพิ่ม
